= The spec file
:description: The YAML file that tells tib what to generate, and its JSON Schema.

A spec is a YAML file that says what tib generates: the service, its template pack, and its
entities with their fields and relations. The commands that read it, `tib init service --spec`
and `tib generate entity --spec`, are being built; the
https://github.com/mryakar/tib-cli/blob/main/ROADMAP.md[roadmap] lists them.

== What the file may leave out

tib fills in what the file does not say, always the same way:

* The pack is `default`.
* An entity's table is its name in upper snake case, `VEHICLE`; a field's column is its name in
  upper snake case, `PLATE_NUMBER`.
* An entity's identifier is a `Long` named `id` that the database assigns (`identity`); a `UUID`
  identifier is generated by the application (`uuid`).
* A field accepts null and is not unique. A `String` without a length gets one from the pack.
* A relation's field is the target's name in lower camel case, `depot`, and its column that name
  in upper snake case with `_ID`, `DEPOT_ID`.
* An entity is not audited, and gets DTOs, a mapper and pagination, but no events.

== The schema

`tib schema` prints the JSON Schema of the spec, which an editor uses for completion and
validation:

[source,bash]
----
tib schema > tib.schema.json
----

With the https://marketplace.visualstudio.com/items?itemName=redhat.vscode-yaml[YAML extension]
of VS Code, the first line of the spec names the schema:

[source,yaml]
----
# yaml-language-server: $schema=tib.schema.json
----

In IntelliJ IDEA, map the file to the schema under _Settings › Languages & Frameworks › Schemas and
DTDs › JSON Schema Mappings_.

The schema of this version of tib is also here: xref:attachment$tib-spec.schema.json[tib-spec.schema.json].

== The rules

The schema and `tib` check the same rules; a problem names the value it is about, as in
`entities[0].fields[2].length`.

* `tib` is the version of the spec format, `1`.
* `service` is lower case words joined with hyphens: `vehicle-service`.
* An entity's name is upper camel case; a field's name is lower camel case; a table or column is
  an SQL identifier that needs no quoting. Every entity has a unique name, and every member of an
  entity, its identifier, fields and relations, has a unique name.
* A field's type is one of `String`, `Integer`, `Long`, `BigDecimal`, `Boolean`, `LocalDate`,
  `LocalDateTime`, `Instant` and `UUID`. Only a `String` has a `length`; only a `BigDecimal` has
  a `precision` and a `scale`.
* An identifier's type is `Long` or `UUID`; its strategy is `identity` or `sequence` for a `Long`
  and `uuid` for a `UUID`.
* A relation is `manyToOne` or `oneToOne`, and its target is an entity of the spec.
